# 多組織擴充設計草案

這份文件是未來從「單一組織、多個區/大家/小家」擴充到「同一套系統服務多個獨立組織」時的 schema 與權限邊界草案。它不是可直接執行的 migration，正式導入前需要先備份、在 staging 驗證，並同步更新 Edge Functions 與前端管理流程。

## 邊界原則

- `organizations` 是最高層租戶邊界；所有教會或獨立組織資料都必須掛在同一個 `organization_id` 下。
- API 權限判斷必須同時檢查角色與 `organization_id`，不能只靠 `district_id / big_family_id / small_group_id`。
- 邀請碼、登入 session、稽核紀錄都要保存 `organization_id`，避免跨組織查詢與操作。
- 原本全域唯一的名稱要改成組織內唯一，例如 `districts.name` 應改為 `(organization_id, name)`。

## 目標資料表

需要加入 `organization_id` 的主要資料：

- `districts`
- `big_families`
- `small_groups`
- `members`
- `attendance_weeks`
- `attendance_records`
- `login_invites`
- `audit_logs`
- `app_sessions`

若未來每個組織的週次設定完全一致，`attendance_weeks` 可以維持共用週次；若不同組織可能有不同活動週期或標籤，則應加入 `organization_id`。

## Migration 草案

```sql
begin;

create table if not exists public.organizations (
  id bigint generated by default as identity primary key,
  name text not null,
  slug text not null unique,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint organizations_name_not_blank check (btrim(name) <> ''),
  constraint organizations_slug_not_blank check (btrim(slug) <> '')
);

insert into public.organizations (name, slug)
values ('Topheart', 'topheart')
on conflict (slug) do nothing;

alter table public.districts
add column if not exists organization_id bigint references public.organizations(id);

alter table public.big_families
add column if not exists organization_id bigint references public.organizations(id);

alter table public.small_groups
add column if not exists organization_id bigint references public.organizations(id);

alter table public.members
add column if not exists organization_id bigint references public.organizations(id);

alter table public.login_invites
add column if not exists organization_id bigint references public.organizations(id);

alter table public.audit_logs
add column if not exists organization_id bigint references public.organizations(id);

update public.districts
set organization_id = (select id from public.organizations where slug = 'topheart')
where organization_id is null;

update public.big_families bf
set organization_id = d.organization_id
from public.districts d
where bf.district_id = d.id
and bf.organization_id is null;

update public.small_groups sg
set organization_id = d.organization_id
from public.districts d
where sg.district_id = d.id
and sg.organization_id is null;

update public.members m
set organization_id = d.organization_id
from public.districts d
where m.organization_id is null
and d.id = m.district_id;

update public.members m
set organization_id = bf.organization_id
from public.big_families bf
where m.organization_id is null
and bf.id = m.big_family_id;

update public.members m
set organization_id = sg.organization_id
from public.small_groups sg
where m.organization_id is null
and sg.id = m.small_group_id;

alter table public.districts
alter column organization_id set not null;

alter table public.big_families
alter column organization_id set not null;

alter table public.small_groups
alter column organization_id set not null;

alter table public.members
alter column organization_id set not null;

create unique index if not exists idx_districts_org_name
on public.districts (organization_id, name);

create unique index if not exists idx_big_families_org_district_name
on public.big_families (organization_id, district_id, name);

create index if not exists idx_members_org_active_district
on public.members (organization_id, district_id, role, full_name)
where is_active;

create index if not exists idx_members_org_active_big_family
on public.members (organization_id, big_family_id, role, full_name)
where is_active;

create index if not exists idx_members_org_active_small_group
on public.members (organization_id, small_group_id, role, full_name)
where is_active;

commit;
```

## API 改造順序

1. Session loader 回傳目前登入者的 `organization_id`。
2. 每個讀取成員、組織、邀請碼、點名紀錄的查詢都加上 `organization_id` 篩選。
3. 建立、移動、封存組織時檢查父層與子層的 `organization_id` 必須一致。
4. 稽核紀錄寫入 `organization_id`，日後查詢可依組織分區。
5. 等所有查詢都帶組織條件後，再把舊的全域唯一限制替換成組織內唯一限制。

## 驗證清單

- A 組織管理員看不到 B 組織成員、組織樹、邀請碼與出席導覽。
- 同名區可以出現在不同組織內，但同一組織內不能重複。
- 成員搬移小家時，目標小家與成員必須同一個 `organization_id`。
- 出席導覽摘要、明細與歷史統計都只聚合目前組織。
- `audit_logs` 可以追查同一組織內的操作，且不混入其他組織。
